# PLAYLINE · 플레이라인

**Your tracks. Your flow.** — 좋아하는 곡에, 나만의 흐름을.

곡을 고르고 '점점 신나게', '파도처럼', '운동 코스' 같은 9가지 흐름 중 하나를 정하면, 곡마다 잰 빠르기(BPM)와 소리 크기(RMS)로 듣기 좋은 순서를 추천합니다. 전후 그래프를 비교하고, 직접 듣고, 화살표로 순서를 고친 뒤 저장할 수 있습니다.

**공개 사이트:** https://vlryun-playline-app-mwkkxu.streamlit.app (Streamlit Community Cloud)

> 한동안 아무도 접속하지 않으면 앱이 잠듭니다. 'Yes, get this app back up!'을 누르면 1~2분 뒤 다시 열립니다.
> 배포판에서는 올린 음원이 Streamlit Cloud 서버에서 분석되며, 외부 AI 서비스로는 보내지 않습니다. 같은 기능을 로컬에서도 실행할 수 있습니다(아래).

디자인: 짙은 밤하늘 배경에 홀로그램 CD 빛깔(시안·바이올렛·핑크·앰버)과 투명 케이스 느낌의 패널. 곡 커버는 곡마다 각도가 다른 디스크 장식이며 실제 앨범 이미지가 아닙니다.

## 설치와 실행 (Windows · VS Code)

1. VS Code에서 이 폴더(`playlist-project`)를 엽니다.
2. 터미널(`Ctrl + ``)을 열고 PowerShell에서 아래 명령을 실행합니다.

가상환경을 쓰는 경우(권장):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

> `Activate.ps1` 실행이 막히면 `Set-ExecutionPolicy -Scope Process RemoteSigned` 를 먼저 실행하세요(현재 터미널 창에만 적용).

이미 전역 Python에 라이브러리를 설치했다면 바로 실행해도 됩니다.

```powershell
python -m streamlit run app.py
```

브라우저에서 http://localhost:8501 로 들어가세요(자동으로 열리지 않습니다). 종료는 터미널에서 `Ctrl + C`.

확인한 환경: Windows 11, Python 3.14.3, VS Code 1.145, 버전은 `requirements.txt` 참고.

## 사용 방법

1. **곡 넣기** — **라이브러리** 탭에서 곡을 골라 담고, **파일 올리기** 탭에서 내 MP3·WAV를 올려 같은 플레이리스트에 더합니다. 두 탭은 하나의 플레이리스트를 채우는 두 입구라서, 탭을 바꾸거나 한쪽에서 더해도 이미 담긴 곡은 그대로 있습니다. 음원 없이 써 보려면 '데모 체험'.
2. **어떤 흐름으로 들을까요?** — 9가지 흐름 중 하나를 고릅니다: 점점 신나게 · 점점 차분하게 · 올렸다가 내리기 · 쉬었다가 다시 신나게 · 파도처럼 · 처음부터 확 · 마지막에 터뜨리기 · 빨리 올리고 쭉 유지 · 운동 코스.
3. **첫 곡·마지막 곡 고정**(선택) — 고정한 곡은 자동 배열과 직접 수정에서 움직이지 않습니다.
4. **세부 설정**(선택) — BPM·RMS 반영 비중, 인접 곡 급변 완화. 기본값으로도 충분합니다.
5. **추천 순서 만들기** → 흐름 그래프로 비교 → 화살표로 직접 바꾸기 → '현재 순서 저장'
6. **내보내기** — CSV(순서·곡명·길이·BPM·RMS), JSON(곡 식별 정보·분석값·순서·설정·버전)

### 두 가지 모드

| | 내 음악 분석 | 흐름 체험 데모 |
|---|---|---|
| 값 | 업로드한 파일을 librosa로 계산한 실제 값 | **가상값** (실제 곡 측정값 아님) |
| 재생 | 업로드한 파일만 재생 | 재생 불가 (음원 없음) |
| 표시 | '실제 분석값' 배지 | '예시 데이터 · 가상값' 배지와 안내 |

데모 곡명·아티스트는 2026-11-19에 공개 차트에서 확인했습니다. 출처는 [docs/demo_sources.md](docs/demo_sources.md).

### 알아 둘 점

- **RMS**는 소리 신호 크기의 평균입니다. 감정이나 '신나는 정도'가 아닙니다.
- **BPM**은 곡 전체의 대표 추정값이며 실제 템포의 절반·두 배로 잡힐 수 있습니다. '곡별 분석값 · BPM 해석 조정'에서 ½·×2로 바꿀 수 있습니다(재분석 없음).
- **흐름 점수**는 같은 목록 안에서 BPM·RMS를 0~1로 정규화해 섞은 상대적 배열 지표입니다.
- 무음 파일은 BPM을 추정하지 않고 배열에서 제외합니다. 박자를 찾지 못한 곡은 RMS만으로 점수를 만듭니다.
- 파일당 최대 50MB(`.streamlit/config.toml`의 `maxUploadSize`).
- 음원은 앱이 실행 중인 서버(로컬 PC 또는 Streamlit Cloud)에서만 분석하고 외부 AI 서비스로 보내지 않습니다. 분석에 쓴 임시 파일은 바로 지웁니다.
- **이 창에만 있는 것**: 올린 음원, 저장한 순서(버전), 지금 작업. **파일로 보관하는 것**: 작업 파일(JSON, schema 2 — 곡 출처·측정값 출처·흐름·고정 곡·세부 설정·원래/추천/지금 순서·버전), 곡 순서 표(CSV). 예전 schema 1 JSON도 불러올 수 있습니다.
- 저장한 버전과 업로드한 음원은 **브라우저 세션에만** 있습니다. 새로고침하면 사라지므로 JSON으로 내려받아 두세요. JSON에는 음원이 들어 있지 않으며, 다시 불러온 뒤 같은 음원을 올리면 **파일 내용(SHA-256)이 같을 때만** 연결합니다.

## 하나의 플레이리스트 (제공 음악 + 내 업로드)

| 동작 | 규칙 |
|---|---|
| 라이브러리 'N곡으로 시작' / '선택한 N곡 추가' | 플레이리스트가 없으면 시작, 있으면 뒤에 더함 |
| '플레이리스트를 이 N곡으로 바꾸기' | 지금 곡을 모두 빼고 고른 곡으로 교체 (저장한 순서 목록은 유지) |
| 파일 올리기 '분석해서 추가' | 분석한 곡을 뒤에 더함. 라이브러리 곡은 그대로 |
| 곡 줄의 ✕ | 그 곡만 뺌. 다른 곡의 측정값·빠르기 보정·설정은 그대로 |
| 같은 곡 판단 | **파일 내용(SHA-256)** 기준. 같은 내용이면 한 번만 넣고, 이미 담긴 곡과 같은 파일을 올리면 새로 넣지 않고 듣기만 연결 |
| 제목만 같은 다른 곡 | 다른 곡으로 넣고 제목 뒤에 (2)를 붙여 구분 |
| 순서 | 담은 순서가 '원래 순서'. 지금 순서가 추천 그대로였다면 새 추천을 따르고, 직접 바꾼 상태였다면 그 순서를 지키고 새 곡을 끝(마지막 곡 고정이 있으면 그 앞)에 붙임 |

곡마다 출처(제공 음악 / 내 업로드 / 데모), 들을 수 있는지, 측정값 출처와 범위(사전 분석 또는 올린 파일 분석 · librosa · 곡 전체)를 '곡별 상세 정보'에서 볼 수 있습니다. 데모의 예시 값은 실제 측정값으로 저장·표시하지 않습니다.

## ✏️ 나만의 흐름 (10번째 선택지)

기존 9가지 흐름은 그대로 두고, '✏️ 나만의 흐름'을 고르면 곡선 편집기가 나타납니다.

- **직접 그리기**: 누른 채 움직여 그립니다. 그린 구간만 바뀌고 나머지는 원래 곡선이 남습니다(가로 13칸으로 정리).
- **점으로 다듬기**: 조절점(처음 7개)을 위아래로 끕니다. 가로 위치는 고정이라 순서가 뒤집히지 않습니다. 두 방식은 같은 곡선을 고칩니다.
- **실행 취소 · 초기화 · 기존 흐름에서 시작**(9가지 흐름 중 하나를 불러와 수정. 원래 흐름은 바뀌지 않음).
- 가로축은 곡 순서(처음 → 마지막), 세로축은 흐름 점수의 목표(아래 '차분하게', 위 '신나게', 0~1). 감정을 잰 값이 아닙니다.
- **'이 흐름으로 정렬'**을 눌러야 정렬합니다. 곡선에서 곡 수 N개 자리(같은 간격)의 값을 **선형 보간**으로 뽑아 기존 정렬 알고리즘의 목표로 넘깁니다(`arrange.sample_curve`). 빠르기·소리 크기 비중, 곡 사이 부드럽게 잇기, 처음·마지막 곡 고정이 그대로 적용됩니다.
- 그린 뒤 다시 정렬하지 않으면 '흐름이 바뀌었어요. 다시 정렬해 주세요'가 뜨고, 편집기에 마지막으로 정렬에 쓴 흐름이 주황 점선으로 보입니다.
- 편집기는 `st.components.v2` 컴포넌트(`playline/curve_editor.py`)입니다. 드래그 중에는 편집기 안에서만 다시 그리고, 손을 뗄 때 한 번만 곡선을 Python으로 보냅니다.
- 작업 파일·저장한 순서의 설정에 곡선(`settings.curve`)이 함께 저장됩니다. 곡선이 없는 예전 파일도 열립니다.

## 왜 여기에?

곡 줄 아래 '왜 여기에?'를 누르면 그 곡의 배치 근거를 **실제 계산값**으로 펼쳐 보여 줍니다(`playline/explain.py`, 외부 AI 없이 문장 틀 사용).

- 전체 N곡 중 몇 번째인지, 목표 곡선 주변 값으로 본 구간(시작·마무리·올라감·내려감·유지·꼭대기·바닥)
- 이 위치의 목표 점수, 이 곡의 흐름 점수, 두 값의 차이 — 정렬·그래프·지표에 쓴 값과 같고, 같은 0~1 눈금 막대로 비교
- 원래 순서 → 추천 순서(→ 직접 바꾼 지금 순서) 위치
- 흐름 점수 계산식(빠르기·소리 크기의 목록 안 위치 × 비중)
- 고정한 곡은 고정 사실을 먼저, 직접 순서를 바꿨으면 그 사실을 먼저 알리고, 설정을 바꾼 뒤 다시 추천하지 않았으면 안내만 보여 줍니다.
- 정렬은 전체 곡의 배치와 '곡 사이 부드럽게 잇기'를 함께 고려하므로, 이 값은 '이 위치와 곡의 점수 비교'이지 이 곡이 최적이라 뽑혔다는 뜻이 아닙니다.

## 플레이어

화면 아래 고정 플레이어로 플레이리스트를 이어 듣습니다.

- 재생을 누르기 전에는 소리가 나지 않습니다. 오디오는 하나뿐이라 두 곡이 겹치지 않습니다.
- 이전·재생/일시정지·다음, 진행 막대(눌러서 이동), 곡이 끝나면 다음 곡으로 자동 이동.
- '지금 순서 / 추천 순서 / 원래 순서로 듣기'를 고를 수 있습니다.
- 재생 중에 순서를 바꾸면 지금 곡은 끊기지 않고, 바뀐 순서는 다음 곡부터 적용됩니다.
- 들을 수 없는 곡(음원 없음)은 목록·배열에서 지우지 않고 건너뛰며, 건너뛴 사실을 플레이어에 표시합니다.
- Streamlit이 화면을 다시 그려도 끊기지 않도록 플레이어는 페이지에 한 번만 만들어 둡니다(`playline/player.py`).

## 음원 라이브러리

사용자가 파일을 올리지 않아도 고를 수 있는 곡 목록입니다.

- `data/library.json` — 곡별 **실제 분석값**(BPM·RMS·길이)과 SHA-256. 앱의 업로드 분석과 같은 함수로 계산합니다.
- **들을 수 있는 제공 음악 8곡**: Kevin MacLeod (incompetech.com), CC BY 4.0. 출처·크레디트는 [docs/music_credits.md](docs/music_credits.md)와 앱의 '음악 출처·라이선스'에 있습니다. 이 곡들은 `git add -f`로 저장소에 넣어 공개 사이트에서도 재생됩니다.
- `library/` — 재생용 음원 파일. 공개 사이트에는 들을 수 있는 곡만 둡니다. 저작권 음원은 공개 저장소에 올리지 않습니다(`.gitignore`) — 그런 곡은 각자 '파일 올리기'로 넣어 쓰세요.
- 재배포가 허락된 음원(직접 만든 곡, CC 라이선스 등)만 `git add -f library/파일명`으로 저장소에 넣으면 공개 사이트에서도 재생됩니다.

곡 추가(파일 또는 폴더, 여러 개 가능):

```powershell
python -X utf8 tools\build_library.py "C:\Users\me\Music\song.mp3" --artist "song.mp3=아티스트"
```

곡명은 파일 이름에서 만들며(다운로드 사이트 꼬리표 제거), `--title "파일이름=곡명"`으로 바꿀 수 있습니다. 추가 후 `data/library.json`을 커밋·푸시하면 공개 사이트에 반영됩니다.

## 앨범 커버

- 라이브러리·데모 곡: `python -X utf8 toolsetch_covers.py` 가 Apple iTunes Search API에서 공식 커버 주소를 찾아 JSON에 기록합니다(이미지 파일은 저장소에 넣지 않음). 아티스트가 일치해야 하고, 아티스트를 모르는 곡은 파일 속 커버 그림까지 같아야 확정합니다. 확정하지 못하면 디스크 그림으로 둡니다.

## 자동 배열 방법

1. 곡 목록 안에서 BPM과 평균 RMS를 각각 최소-최대 정규화(값이 모두 같으면 0.5)
2. 흐름 점수 = BPM 정규화값 × 비중 + RMS 정규화값 × (1 − 비중)
3. 흐름별 목표 곡선(`playline/arrange.py`의 `target_shape`: 직선 상승·하강, 60% 정점 삼각형, V자, 두 번 반복 파형, 20% 정점 후 하강, 3제곱 곡선, 빠른 상승 후 유지, 워밍업-유지-쿨다운 사다리꼴)을 목록의 점수 범위에 맞춤
4. 고정하지 않은 곡을 점수 순으로, 남은 자리를 목표값 순으로 정렬해 짝짓기(목표와의 절대 오차 합 최소)
5. '인접 곡 급변 완화' 값 λ만큼 이웃 곡 점수 차이를 함께 고려해, 두 곡의 자리를 바꿔 개선되면 교환을 반복

무작위 요소가 없어 같은 목록·설정이면 항상 같은 결과가 나옵니다.

## 문제 해결

- **`DLL load failed ... 애플리케이션 제어 정책에서 이 파일을 차단했습니다`**: Windows '스마트 앱 컨트롤'이 numba·pandas의 DLL을 처음 불러올 때 막는 경우가 있습니다. 개발 중 두 번 나타났고, 같은 명령을 다시 실행하니 정상 동작했습니다. 계속되면 Windows 보안 설정을 확인해야 합니다.
- **터미널에 한글이 깨지거나 `UnicodeEncodeError`**: 명령에 `-X utf8`을 붙여 실행하세요.
- 첫 분석은 librosa 준비 때문에 곡당 15~20초 정도 걸릴 수 있습니다.
